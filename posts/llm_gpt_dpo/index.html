Overview

In the last post we aligned our instruction-tuned GPT-2 with human preferences the classic way, with RLHF using Proximal Policy Optimization.

In this post we attempt to align our model using Direct Preference Optimization (DPO), which aligns the model without explicit reinforcement learning.

Introduction

Proximal Policy Optimization (PPO) needs a lot of machinery:

  • A Bradley–Terry reward model
  • A rollout sampler
  • Generalized Advantage Estimation (GAE)
  • A critic model
  • Clipped surrogate objective
  • Four copies of the network in memory at once.

With Direct Preference Optimization (DPO), by applying a few lines of algebra on the RLHF objective we can fold the reward model and the reinforcement learning loop into one supervised loss, applied directly to preference pairs.

What we keep from last time:

  • The preference dataset
  • The GPT architecture
  • The Bradley–Terry model
  • The Kullback-Leibler regularized objective
  • and the frozen reference model.

What goes away:

  • the separately trained reward model
  • sampling during training
  • the critic
  • advantages
  • importance ratios.

DPO never sees the reward model we trained last time. That makes the reward model a useful independent judge, so at the end we put SFT, PPO and DPO side by side on the same test prompts for a quick qualitative evaluation.

Deriving the DPO Objective

RLHF maximizes the reward while a KL penalty keeps the policy from drifting too far from the reference

\[ \max_{\pi} \; \mathbb{E}_{x,\, y \sim \pi} \big[ r(x, y) \big] - \beta \, \mathbb{D}_{\mathrm{KL}}\big[ \pi(\cdot \mid x) \,\|\, \pi_{\mathrm{ref}}(\cdot \mid x) \big] \]

For a fixed reward, this objective has a closed-form solution. The objective can be rewritten as \(-\beta\,\mathbb{D}_{\mathrm{KL}}[\pi \,\|\, \pi^*]\) plus a term that doesn’t depend on \(\pi\), so it is maximized at

\[ \pi^*(y \mid x) = \frac{1}{Z(x)} \, \pi_{\mathrm{ref}}(y \mid x) \, e^{r(x, y)/\beta} \]

The partition function \(Z(x)\) sums over every possible response, which is not feasible to obtain, so we can’t compute it. That is why RLHF falls back on reinforcement learning.

DPO takes the log of both sides and solves for the reward instead

\[ r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)} + \beta \log Z(x) \]

The troublesome \(Z(x)\) now depends only on the prompt. The Bradley–Terry model from last post depends only on the difference between the rewards of two responses to the same prompt, so \(\beta \log Z(x)\) cancels out. Replacing \(\pi^*\) with our trainable policy \(\pi_\theta\) defines the implicit reward

\[ \hat{r}_\theta(x, y) = \beta \log \frac{\pi_\theta(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)}, \]

and the Bradley–Terry negative log-likelihood becomes the DPO loss

\[ \mathcal{L}_{\mathrm{DPO}}(\theta) = -\,\mathbb{E}_{(x, y_w, y_l)} \Big[ \log \sigma\big( \hat{r}_\theta(x, y_w) - \hat{r}_\theta(x, y_l) \big) \Big] \]

This is the last post’s reward-model loss with the reward head swapped for \(\hat{r}_\theta\). Fitting it no longer produces a reward model. It produces the aligned policy directly. To compute it, all we need is \(\log \pi(y \mid x)\) for each response under both the policy and the reference.

def format_input(entry):

    instruction_text = (
        f"Below is an instruction that describes a task. "
        f"Write a response that appropriately completes the request."
        f"\n\n### Instruction:\n{entry['instruction']}"
        )

    input_text = (
        f"\n\n### Input:\n{entry['input']}" if entry["input"] else ""
        )
    return instruction_text + input_text

Loading

Again we load in the same tokenizer as before.

tokenizer = tiktoken.get_encoding("gpt2")

As before, each entry becomes two token sequences, one for chosen and one for rejected. Each is the prompt followed by the response, terminated with <|endoftext|>. What changes is the mask.

The reward model read one score at the final token, so its mask only had to say where each sequence ended. DPO instead needs the log-probability the model assigns to the response given the prompt, which is the sum of the per-token log-probabilities:

\[ \log \pi(y \mid x) = \sum_{t} \log \pi(y_t \mid x, y_{<t}) \]

That sum must only cover the response tokens. The prompt is identical in both members of a pair, so it carries no preference information, and padding isn’t text at all. We therefore build a response mask directly in the \(T{-}1\) next-token grid that token_logprobs produces, where output position \(t\) scores token \(t{+}1\). The mask is 1.0 at every position that predicts a response token, including the appended <|endoftext|>.

We tokenize the prompt and the response separately and concatenate the ids. That tells us exactly where the prompt ends, and it matches generation time, when the model sees the prompt encoded on its own.

PAD_ID = EOS_ID = 50256  # <|endoftext|> plays both roles, as in the previous posts


@dataclass
class PreferenceDataset:
    """Pre-encodes every preference pair; each item holds the prompt length plus a chosen and a rejected token sequence."""
    data: list

    def __post_init__(self):
        self.encoded = []
        for entry in self.data:
            prompt_ids = tokenizer.encode(format_input(entry) + "\n\n### Response:\n")
            self.encoded.append({
                "prompt_len": len(prompt_ids),
                "chosen": prompt_ids + tokenizer.encode(entry["chosen"]) + [EOS_ID],
                "rejected": prompt_ids + tokenizer.encode(entry["rejected"]) + [EOS_ID],
            })

    def __len__(self):
        return len(self.data)

    def __getitem__(self, idx: int):
        return self.encoded[idx]


def preference_collate_fn(batch, pad_token_id=PAD_ID, allowed_max_length=256):
    longest_seq = max(max(len(item["chosen"]), len(item["rejected"])) for item in batch)
    batch_max_length = min(
        longest_seq,
        allowed_max_length,
    )

    def pad_and_stack(key):
        ids, mask = [], []
        for item in batch:
            seq = item[key][:allowed_max_length]
            ids.append(np.array(seq + [pad_token_id] * (batch_max_length - len(seq))))
            # response mask in the T-1 next-token grid: position t predicts token t+1
            response_mask = np.zeros(batch_max_length - 1, dtype=np.float32)
            response_mask[item["prompt_len"] - 1:len(seq) - 1] = 1.0
            mask.append(response_mask)
        return np.stack(ids), np.stack(mask)

    chosen_ids, chosen_mask = pad_and_stack("chosen")
    rejected_ids, rejected_mask = pad_and_stack("rejected")
    return chosen_ids, chosen_mask, rejected_ids, rejected_mask

With a dataset and a collate function, we wrap everything in a grain data loader.

def load_and_preprocess_data(data: list, batch_size: int, shuffle=False):

    dataset = PreferenceDataset(data)

    print(f"Loaded {len(dataset)} samples")

        operations=[
            pygrain.Batch(batch_size=batch_size, drop_remainder=True, batch_fn=preference_collate_fn)

    return dl

Load Pretrained GPT

The architecture is identical to the RLHF post, including the hidden_states() / __call__ split. DPO itself doesn’t use that seam. We keep it because in a later section we load the last post’s reward model, which puts a scalar head on the same backbone, to judge our results.

Dropout stays off, because the DPO loss compares how likely a response is under the policy with how likely it is under a frozen reference. At step 0 the two models have identical weights, so every one of those comparisons should come out exactly equal. With dropout active they would differ by random noise before we had learned anything.

@dataclass
class GPTConfig:
    vocab_size: int = 50_257
    context_length: int = 256
    d_model: int = 768
    num_heads: int = 12
    num_layers: int = 12
    d_ff: int = 0
    dropout_rate: float = 0.1
    mha_dropout_rate: float = 0.1

    def __post_init__(self):
        if self.d_ff == 0:
            self.d_ff = 4 * self.d_model

    def __getitem__(self, key: str):

class MultiHeadAttention(nnx.Module):
    """Multi-head self-attention module"""
    def __init__(self, d_model, num_heads, dropout_rate, *, rngs: nnx.Rngs):
        assert d_model % num_heads == 0, f"d_model ({d_model}) must be divisible by num_heads ({num_heads})"
        self.num_heads = num_heads
        self.d_model = d_model
        self.head_dim = d_model // num_heads
        self.q_proj = nnx.Linear(d_model, d_model, rngs=rngs)
        self.k_proj = nnx.Linear(d_model, d_model, rngs=rngs)
        self.v_proj = nnx.Linear(d_model, d_model, rngs=rngs)
        self.out_proj = nnx.Linear(d_model, d_model, rngs=rngs)

        self.dropout = nnx.Dropout(rate=dropout_rate, rngs=rngs)

    def _split_heads(self, x, batch, seq_len):
        return x.reshape(batch, seq_len, self.num_heads, self.head_dim).transpose(0, 2, 1, 3)

    def __call__(self, x):
        batch, seq_len, _ = x.shape
        mask = jnp.triu(jnp.ones((seq_len, seq_len), dtype=bool), 1)

        q = self._split_heads(self.q_proj(x), batch, seq_len)
        k = self._split_heads(self.k_proj(x), batch, seq_len)
        v = self._split_heads(self.v_proj(x), batch, seq_len)

        attn_logits = jnp.matmul(q, k.transpose(0, 1, 3, 2)) / jnp.sqrt(self.head_dim)
        attn_logits = jnp.where(mask, -jnp.inf, attn_logits)

        attn_weights = jax.nn.softmax(attn_logits, axis=-1)
        attn_weights = self.dropout(attn_weights)
        out = jnp.matmul(attn_weights, v).transpose(0, 2, 1, 3).reshape(batch, seq_len, self.d_model)
        return self.out_proj(out)


class FeedForward(nnx.Module):
    """Position-wise feedforward network as used in the Transformer"""
    def __init__(self, d_model, d_ff, *, rngs: nnx.Rngs):
        self.linear1 = nnx.Linear(d_model, d_ff, rngs=rngs)
        self.linear2 = nnx.Linear(d_ff, d_model, rngs=rngs)

    def __call__(self, x):
        x = self.linear1(x)
        x = jax.nn.gelu(x)
        return self.linear2(x)


class TransformerBlock(nnx.Module):
    """Single Transformer block: multi-head self-attention followed by a feedforward network, with residual connections and layer normalization."""
    def __init__(self, d_model, num_heads, d_ff, mha_dropout_rate, dropout_rate, *, rngs: nnx.Rngs):
        self.attention = MultiHeadAttention(d_model, num_heads, mha_dropout_rate, rngs=rngs)
        self.norm1 = nnx.LayerNorm(d_model, rngs=rngs)
        self.ffn = FeedForward(d_model, d_ff, rngs=rngs)
        self.norm2 = nnx.LayerNorm(d_model, rngs=rngs)

        self.dropout = nnx.Dropout(rate=dropout_rate, rngs=rngs)

    def __call__(self, x):
        shortcut = x
        x = self.norm1(x)
        x = self.attention(x)
        x = self.dropout(x)
        x = x + shortcut

        shortcut = x
        x = self.norm2(x)
        x = self.ffn(x)
        x = self.dropout(x)
        x = x + shortcut
        return x


class GPT(nnx.Module):
    def __init__(self, config: GPTConfig, *, rngs: nnx.Rngs):
        # Token and Position Embeddings
        self.token_emb = nnx.Embed(config["vocab_size"], config["d_model"], rngs=rngs)
        self.pos_emb = nnx.Param(jax.random.normal(rngs.params(), (1, config["context_length"], config["d_model"])) * 0.02)
        self.drop_emb = nnx.Dropout(rate=config["dropout_rate"], rngs=rngs)

        # Transformer Blocks
        self.blocks = nnx.List([TransformerBlock(config["d_model"], config["num_heads"], config["d_ff"], config["mha_dropout_rate"], config["dropout_rate"], rngs=rngs) for _ in range(config["num_layers"])])
        self.norm_final = nnx.LayerNorm(config["d_model"], rngs=rngs)

        # Logits
        self.out_head = nnx.Linear(config["d_model"], config["vocab_size"], rngs=rngs)

    def hidden_states(self, input_ids):
        """Everything except the output head -- the seam where other heads plug in."""
        _, seq_len = input_ids.shape

        # Combine embeddings: Token + Position
        x = self.token_emb(input_ids)
        x = x + self.pos_emb[:, :seq_len, :]

        x = self.drop_emb(x)
        for block in self.blocks:
            x = block(x)
        return self.norm_final(x)

    def __call__(self, input_ids):
        return self.out_head(self.hidden_states(input_ids))

def restore_checkpoint(model, checkpoint_dir):
    """Restore an Orbax checkpoint into an already-constructed model of the same structure."""
    checkpointer = orbax.PyTreeCheckpointer()
    restored_state = checkpointer.restore(
        checkpoint_dir.absolute(),
        args=orbax.args.PyTreeRestore(nnx.state(model)),
    )
    nnx.update(model, restored_state)
    return model

Training with DPO

The policy starts as the SFT model and is the only model we train. The reference is a frozen clone of the same weights.

policy_model = load_sft_model()
reference_model = nnx.clone(policy_model)

Sequence log-probabilities

token_logprobs is reused from the PPO rollout-scoring code, where one forward pass over a finished sequence gives the log-probability of every next token at once. Summing its output under the response mask gives \(\log \pi(y \mid x)\) for the whole response.

def token_logprobs(model, sequences):
    """Log-probability the model assigns to each next token: output[:, t] scores sequences[:, t+1]."""
    logits = model(sequences[:, :-1])
    logps = jax.nn.log_softmax(logits, axis=-1)
    return jnp.take_along_axis(logps, sequences[:, 1:, None], axis=-1).squeeze(-1)


def sequence_logprob(model, sequences, response_mask):
    """log pi(y | x): the summed log-probability of the response tokens only."""
    return jnp.sum(token_logprobs(model, sequences) * response_mask, axis=-1)

The DPO loss

The dpo_loss_fn follows last post’s rm_loss_fn exactly. Where rm_loss_fn read two scalar scores off a reward head, this version computes two implicit rewards from log-probability ratios. Gradients are taken only with respect to the policy, so no gradient flows into the reference.

Besides the loss we track the diagnostics that DPO trainers usually report:

  • Reward accuracy is the fraction of pairs whose implicit reward ranks the chosen response above the rejected response. It corresponds to the reward model’s accuracy, with the difference that at step 0 every margin is exactly zero, so accuracy starts at 0% rather than 50%. A tie doesn’t count as a correct ranking.

  • Chosen and rejected rewards, \(\hat{r}_\theta(x, y_w)\) and \(\hat{r}_\theta(x, y_l)\), are tracked separately. The loss only sees their difference, but the individual values show how the gap widens, where chosen responses become more likely, rejected responses become less likely, or some mix of the two.

We use a small \(\beta\) because the implicit rewards live on a log-probability scale. Summed over a 20-token response, log-ratios of several nats appear quickly, and \(\beta = 0.1\) keeps the sigmoid’s input in a sensible range. The DPO paper uses 0.1 for most of its experiments. For the optimizer we reuse the PPO policy’s recipe with a smaller learning rate, since every step now moves the policy with a full gradient on clean supervised pairs.

DPO_BETA = 0.1
DPO_LR = 5e-6

def dpo_loss_fn(policy, reference, chosen_ids, chosen_mask, rejected_ids, rejected_mask, beta=DPO_BETA):
    policy_chosen = sequence_logprob(policy, chosen_ids, chosen_mask)
    policy_rejected = sequence_logprob(policy, rejected_ids, rejected_mask)
    ref_chosen = jax.lax.stop_gradient(sequence_logprob(reference, chosen_ids, chosen_mask))
    ref_rejected = jax.lax.stop_gradient(sequence_logprob(reference, rejected_ids, rejected_mask))

    chosen_rewards = beta * (policy_chosen - ref_chosen) # implicit reward r(x, y_w)
    rejected_rewards = beta * (policy_rejected - ref_rejected) # implicit reward r(x, y_l)
    margin = chosen_rewards - rejected_rewards
    loss = -jnp.mean(jax.nn.log_sigmoid(margin)) # the same Bradley-Terry negative log-likelihood as the reward model
    stats = {
        "accuracy": jnp.mean((margin > 0).astype(jnp.float32)),
        "chosen_reward": jnp.mean(chosen_rewards),
        "rejected_reward": jnp.mean(rejected_rewards),
    }
    return loss, stats


dpo_optimizer = nnx.Optimizer(
    policy_model,
    optax.chain(optax.clip_by_global_norm(1.0), optax.adamw(DPO_LR, weight_decay=0.0)),
    wrt=nnx.Param,
)


@nnx.jit
def dpo_train_step(policy, reference, optimizer, chosen_ids, chosen_mask, rejected_ids, rejected_mask):
    (loss, stats), grads = nnx.value_and_grad(dpo_loss_fn, has_aux=True)(
        policy, reference, chosen_ids, chosen_mask, rejected_ids, rejected_mask
    )
    optimizer.update(policy, grads)
    return loss, stats


@nnx.jit
def dpo_eval_step(policy, reference, chosen_ids, chosen_mask, rejected_ids, rejected_mask):
    return dpo_loss_fn(policy, reference, chosen_ids, chosen_mask, rejected_ids, rejected_mask)

Training

We again reuse the same reward-model training loop, but now with the step function swapped out. There is no rollout phase and there are no inner PPO epochs, only minibatches of preference pairs. Each step runs four forward passes (policy and reference, on both chosen and rejected responses) and one backward pass through the policy.

The reference never changes, so its log-probabilities for each pair are constants. Large-scale implementations often compute them once, in a single pass over the dataset, and then drop the reference from memory during training. We compute them on the fly to keep the code short.

We train for one epoch. Our preferences are deterministic (the polite response always wins), so the DPO loss keeps asking for a larger margin no matter how far the policy has already moved. Extra epochs mostly push the policy further from the reference.

num_epochs = 1
batch_size = 8
num_examples = len(train_data)

eval_freq = 10
eval_iter = 6

dpo_loss_history = []
dpo_val_loss_history = []
dpo_accuracy_history = []
chosen_reward_history = []
rejected_reward_history = []
pairs_seen_history = []
pairs_seen = 0
ema_loss = None
val_ema_loss = None
alpha = 0.3

for epoch in range(num_epochs):
    train_batch_iter = iter(train_dl)

    for step, batch in tqdm(enumerate(train_batch_iter), total=num_examples // batch_size):
        loss, stats = dpo_train_step(policy_model, reference_model, dpo_optimizer, *batch)
        pairs_seen += batch[0].shape[0]

        if step > 0 and step % eval_freq == 0:
            loss_val = float(loss)
            ema_loss = loss_val if ema_loss is None else alpha * loss_val + (1 - alpha) * ema_loss
            dpo_loss_history.append(ema_loss)
            dpo_accuracy_history.append(float(stats["accuracy"]))
            chosen_reward_history.append(float(stats["chosen_reward"]))
            rejected_reward_history.append(float(stats["rejected_reward"]))
            pairs_seen_history.append(pairs_seen)

            val_losses = [
                float(dpo_eval_step(policy_model, reference_model, *val_batch)[0])
                for val_batch in itertools.islice(iter(val_dl), eval_iter)
            ]
            if val_losses:
                val_ema_loss = (
                    alpha * np.mean(val_losses) + (1 - alpha) * val_ema_loss
                    if val_ema_loss is not None else np.mean(val_losses)
                )
                dpo_val_loss_history.append(float(val_ema_loss))

Evaluations

We compare three models on test prompts none of them have seen. We include the SFT reference we started from, the PPO policy from the last post, and the new DPO policy, all decoded greedily.

To score the responses we bring back the last post’s reward model. When we evaluated PPO, we had to add the caveat that the policy was graded with the same reward model it had been optimized against. DPO, however, never saw that reward model. It learned from the same preference pairs, but never from the reward model’s scores, so for DPO the reward model acts as an independent judge. PPO still has a home-field advantage, since it was optimized directly for these scores, so keep that in mind when you compare the numbers. As before, the printed text lets you be the final judge.

class RewardModel(nnx.Module):
    """A GPT backbone with a scalar head instead of a vocabulary head.

    Returns one score per position; the meaningful one is at the sequence's final
    real token. The backbone keeps its (unused) vocabulary head -- a small memory
    tax for not having to fiddle with checkpoint structure.
    """
    def __init__(self, backbone: GPT, d_model: int, *, rngs: nnx.Rngs):
        self.backbone = backbone
        self.reward_head = nnx.Linear(d_model, 1, kernel_init=nnx.initializers.zeros_init(), rngs=rngs)

    def __call__(self, input_ids):
        h = self.backbone.hidden_states(input_ids)
        return self.reward_head(h).squeeze(-1)  # (batch, seq_len)

def generate_greedy(model, prompt_ids, max_new_tokens=MAX_NEW_TOKENS, eos_id=EOS_ID):
    idx = jnp.asarray(np.asarray(prompt_ids))[None, :]
    for _ in range(max_new_tokens):
        logits = model(idx)[:, -1, :]
        next_token = jnp.argmax(logits, axis=-1, keepdims=True)
        if int(next_token[0, 0]) == eos_id:
            break
        idx = jnp.concatenate([idx, next_token], axis=1)
    return np.asarray(idx)[0]

Conclusion

In this post we aligned the same SFT model to the same preferences as the last post, without a separately trained reward model, without sampling, and without a critic:

  1. Starting from the KL-regularized RLHF objective, we derived its closed-form optimal policy, \(\pi^* \propto \pi_{\mathrm{ref}} e^{\frac{r}{\beta}}\).

  2. Inverting that result showed that every policy defines an implicit reward, \(\beta \log \frac{\pi}{\pi_{\mathrm{ref}}}\), up to a term that depends only on the prompt.

  3. Inside the Bradley–Terry model that prompt-only term cancels. What’s left is a supervised loss on preference pairs that trains the policy directly.

The cost of DPO’s simplicity is that it learns in an offline paradigm. The policy trains only on responses someone else wrote and never sees the consequences of its own generations. PPO samples from the current policy, so it can discover and correct its own failures, and a single reward model can score an unlimited stream of new samples. In practice DPO is popular because it is cheap and stable, while on-policy RL remains the tool of choice when a good reward signal is available.
